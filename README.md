# 发货工作台

## 登录与账号

所有工作空间 API 都要求登录。密码使用 PBKDF2-SHA256（100,000 次迭代）加盐哈希保存，登录会话使用 HttpOnly、Secure、SameSite=Strict Cookie，并在 12 小时后失效。管理员可在网页右上角创建普通账号、重置密码、停用或启用账号；普通账号不能进入账号管理。

私有发货辅助网站，使用 Sites / React / D1。商品、通用路径及最近 30 个导入批次存入共享数据库，不依赖浏览器本地缓存。发布源码不包含真实发货数据；用户打开网站后自行上传表格，只保存 SKU 和数量，不保存订单号、地址等无关字段。

## 使用

1. 通用路径：可选，建立名称与完整路径的对应关系。
2. 商品资料：可以单件录入，也可以下载 Excel 模板后批量导入产品货号、选填名称、产品模式、必选的排版分类（设计排版或非设计排版）、产品分类、是否需要打印、图片链接、最多 60 个字符的备注，以及成对的源/目标路径。产品模式和产品分类分别由选项管理统一维护；旧版二级分类不再显示或导入。产品货号必填且全局唯一，产品名称可留空且填写后须唯一。商品列表分页展示，可选择每页 10、30 或 50 条；列表支持多选并按需批量修改资料，未勾选的字段保持不变。旧商品的是否打印默认按“否”处理。
3. 发货处理：一次只允许上传一张 XLSX 或 CSV；确认或取消当前表格后才能上传下一张。除 SKU 和发货数量外，还会映射收货仓库、店铺和包裹号并保存到批次明细。
4. 在预览中补齐未匹配产品，下载三列表格或四列复制 CSV。设计排版且不需要打印的商品无需路径；产品模式为“定制”时也可以不配置路径。没有路径的商品不会进入复制 CSV，已有路径的定制商品仍会正常导出。所有商品仍保留在发货统计和发货清单中。复制任务按“是否打印”导出为 `file_list_是.csv` 和 `file_list_否.csv`；两个文件均为无 BOM 的 GBK（Windows 代码页 936）文本，供未修改代码页的中文 Windows BAT 直接读取，不是 XLS 工作簿。
5. “模式汇总表”生成“汇总”“纸质产品”“定制挂历”“设计作图产品”和“下载订单与合并订单”五个 Sheet。新增的订单 Sheet 按订单号汇总不打印商品与需要打印的设计排版商品，并单独汇总需要打印的设计排版订单。各表都有合计项，并纵向合并同一分组的重复内容；包裹数量按包裹号去重。

同一个完整 SKU 的数量相加；不同 SKU 即使属于同一个产品，也不会合并。产品匹配使用 SKU 第一个 ASCII `-` 前的字符串，保持大小写及前导零。各模式总数按发货件数统计，不因多路径重复计数。CSV 每组路径产生一行，每行使用同一个 SKU 和合并数量。文件名不自动加扩展名。

路径仅作为文本记录，网站不会访问电脑上的文件，也不会执行复制。图片由浏览器请求网络链接，失效不会阻止保存。通用路径更新会影响引用它的商品；被引用的通用路径不可删除。完整备份可在商品资料页下载和恢复。

## 运行与验证

- `pnpm install`；本项目需要批准 esbuild、sharp、workerd 的安装脚本，批准记录在 pnpm-workspace.yaml。
- `pnpm dev`：本地预览，D1 数据在 .wrangler 内持久保存。
- `pnpm test`：汇总、验证、路径、商品批量导入、CSV 与 XLSX 导出测试。设置 SAMPLE_WORKBOOK 后会额外核对实际样表。
- `node tests/api-check.mjs`：仅对本地预览检查持久保存、并发冲突、备注长度与同源限制，并删除临时测试商品。
- `pnpm db:generate`：生成数据库迁移；`pnpm build`：发布构建。

线上 API 要求平台认证身份，站点访问权限默认保持仅所有者可访问。不应将带有商品资料的站点改为公开访问。对工作空间的修改均有版本号检查，过期更新返回冲突提示。
